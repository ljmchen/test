utils/rotation.py

旋转表示的瑞士军刀
四元数 / 矩阵 / 6D 互转

整个项目用 6D 旋转喂网络，但数据集里是轴角、可视化要四元数、算误差要矩阵。这个文件就是它们之间的"翻译官"。最核心的是 rotation_6d_to_matrix——把网络吐出的 6 个数变回一个合法旋转矩阵。

def rotation_6d_to_matrix(d6: torch.Tensor) -> torch.Tensor:
    """Convert 6D rotation representation to rotation matrices via Gram-Schmidt."""
    a1, a2 = d6[..., :3], d6[..., 3:6]          # 把 6 个数拆成两个 3 维向量
    b1 = F.normalize(a1, dim=-1)                # 第一行：直接归一化成单位向量
    b2 = a2 - (b1 * a2).sum(dim=-1, keepdim=True) * b1  # 第二行：减去在 b1 上的投影 → 与 b1 正交
    b2 = F.normalize(b2, dim=-1)                # 再归一化
    b3 = torch.cross(b1, b2, dim=-1)            # 第三行：前两行叉乘，自动正交且右手系
    return torch.stack([b1, b2, b3], dim=-2)    # 堆成 (...,3,3) 旋转矩阵

a1,a2 网络只需要给出"任意" 6 个数，不必保证正交。

b2 = a2 − (b1·a2)·b1 这就是 Gram–Schmidt 正交化的精髓：把 a2 中"和 b1 平行的部分"扣掉，剩下的就垂直于 b1。

b3 = b1 × b2 叉乘保证第三轴既垂直前两轴、又构成右手坐标系（合法旋转的行列式 = +1）。

🔑 为什么这是"连续"表示
不论网络输出什么 6 个数（只要 a1、a2 不平行），都能被"修"成一个合法旋转矩阵，且输出微小变化→旋转微小变化。这就避免了四元数的二义性和欧拉角的万向锁，回归任务里梯度更稳。

其它互转函数（同一套思路）

  • quaternion_to_matrix：按 wxyz（实部在前）约定把四元数展开成 3×3 矩阵；
  • matrix_to_rotation_6d：取矩阵前两行拍平成 6 维（6D 的定义）；
  • matrix_to_quaternion：用迹(trace)分支法反解四元数（数值稳定，带 clamp 防开根号负数）；
  • quaternion_to_rotation_6d / rotation_6d_to_quaternion：组合上面几个，一步到位。
💡 约定要记牢
本项目四元数一律 wxyz（实部 w 在最前）。换库对接时这是最常见的踩坑点。

models/pointnet2.py

模块① 点云编码器
4096 点 → 64 个几何 token

文件结构：几个纯函数（knn / FPS / 球查询 / 索引）+ 一个 SetAbstraction 层 + 把 3 个 SA 层串起来的 PointNet2Encoder。

四个基础函数

def farthest_point_sample(xyz, npoint):
    """从 N 个点里挑 npoint 个'彼此最远'的点，返回它们的下标。"""
    B, N, _ = xyz.shape
    centroids = torch.zeros(B, npoint, dtype=torch.long, device=xyz.device)
    distance = torch.full((B, N), 1e10, device=xyz.device)   # 每点到"已选集合"的最近距离
    farthest = torch.randint(0, N, (B,), device=xyz.device)  # 随机选第一个点
    for i in range(npoint):
        centroids[:, i] = farthest                # 收录当前最远点
        centroid = xyz[torch.arange(B), farthest].unsqueeze(1)
        dist = torch.sum((xyz - centroid) ** 2, dim=-1)  # 所有点到它的距离
        distance = torch.min(distance, dist)      # 更新"到已选集合的最近距离"
        farthest = distance.argmax(dim=-1)        # 下一个最远点 = 当前最大最近距离者
    return centroids
🧩 FPS 在干嘛
贪心地一个个挑点，每次都挑"离已选点群最远"的那个。效果是选出的点均匀铺满整个物体，不会扎堆。这样下采样后仍能覆盖整体形状。
def ball_query(xyz, new_xyz, radius, nsample):
    """对每个中心点，找半径内的邻居；不足 nsample 个就用最近点补。"""
    dist = torch.cdist(new_xyz, xyz)              # 中心点到所有点的距离矩阵
    _, idx = dist.topk(nsample, largest=False)    # 先取最近的 nsample 个
    mask = dist.gather(-1, idx) > radius          # 标记其中超出半径的
    first_idx = idx[:, :, 0:1].expand_as(idx)
    idx[mask] = first_idx[mask]                   # 超界的用"最近邻"顶替（等价于丢弃）
    return idx

topk(largest=False) 这里用"取最近 nsample 个"近似真正的球查询，纯张量算子、无需 CUDA 扩展。

idx[mask]=first_idx 半径外的邻居用第 0 个（最近）邻居替换，相当于"凑数但不引入远点噪声"。

knn（基于 torch.cdist 找 k 近邻）和 index_points（按下标取点，处理好 batch 维广播）是两个小工具，服务于上面两个函数。

SetAbstraction：一个"采样-分组-聚合"层

class SetAbstraction(nn.Module):
    def __init__(self, npoint, radius, nsample, in_channel, mlp_channels):
        ...
        last_channel = in_channel + 3            # +3：每个邻居要额外带"相对中心的 xyz"
        for out_channel in mlp_channels:         # 一串 Conv1d+BN+ReLU
            layers += [nn.Conv1d(last_channel, out_channel, 1),
                       nn.BatchNorm1d(out_channel), nn.ReLU(inplace=True)]
            last_channel = out_channel
        self.mlp = nn.Sequential(*layers)

    def forward(self, xyz, features=None):
        fps_idx = farthest_point_sample(xyz, self.npoint)   # ① 采样中心点
        new_xyz = index_points(xyz, fps_idx)
        group_idx = ball_query(xyz, new_xyz, self.radius, self.nsample)  # ② 分组
        grouped_xyz = index_points(xyz, group_idx)
        grouped_xyz -= new_xyz.unsqueeze(2)      # 关键：邻居坐标改成"相对中心"的局部坐标
        if features is not None:
            grouped_features = index_points(features, group_idx)
            grouped_features = torch.cat([grouped_xyz, grouped_features], dim=-1)
        else:
            grouped_features = grouped_xyz
        grouped_features = grouped_features.reshape(B*self.npoint, self.nsample, -1).permute(0,2,1)
        grouped_features = self.mlp(grouped_features)        # ③ 共享 MLP 提特征
        new_features = grouped_features.max(dim=-1).values   # ③ 组内最大池化 → 中心点新特征
        return new_xyz, new_features.reshape(B, self.npoint, -1)

grouped_xyz -= new_xyz 把邻居换成相对中心的局部坐标，这样学到的特征具有平移不变性（物体挪个位置，局部几何不变）。

in_channel + 3 拼接顺序是 [相对坐标(3), 上一层特征]，所以 MLP 输入通道要 +3。

max(dim=-1) 对组内 nsample 个邻居取逐通道最大值——这是 PointNet 系列的标志性操作，对点的顺序不敏感（置换不变）。

PointNet2Encoder：三层堆叠

self.sa1 = SetAbstraction(512, 0.1, 32, self.feature_dim, [64, 64, 128])
self.sa2 = SetAbstraction(128, 0.2, 64, 128,               [128, 128, 256])
self.sa3 = SetAbstraction(num_output_tokens, 0.4, 64, 256, [256, 256, output_dim])

def forward(self, xyz, features=None):
    if self.feature_dim == 0:        # in_channels==3 → xyz-only，丢弃颜色
        features = None
    xyz1, feat1 = self.sa1(xyz, features)   # 4096 → 512
    xyz2, feat2 = self.sa2(xyz1, feat1)     # 512  → 128
    _,    feat3 = self.sa3(xyz2, feat2)     # 128  → 64（num_output_tokens）
    return feat3                            # (B, 64, output_dim=256)
⚠️ xyz-only 的自适应
feature_dim = in_channels - 3。当配置 pc_in_channels=3 时 feature_dim==0，forward 里把传进来的颜色直接置 None，避免首层 Conv 通道数对不上而崩溃。这就是为什么 encode_condition 可以"无脑"永远传 rgb。

models/flow_matching.py

模块⑤ 生成核心
DiT 风格速度场 v(x_t, t, c)

三个零件：sinusoidal_embedding（时间编码）、AdaLayerNorm（注入时间）、FlowMatchingBlock（一层），再由 FlowMatchingTransformer 组装。

时间编码与 AdaLN

def sinusoidal_embedding(timesteps, dim):
    """把标量时间 t 变成一段高低频正余弦向量（和 Transformer 位置编码同源）。"""
    half = dim // 2
    freqs = torch.exp(-math.log(10000.0) * torch.arange(half, device=timesteps.device) / half)
    args = timesteps.unsqueeze(-1) * freqs.unsqueeze(0)
    return torch.cat([torch.cos(args), torch.sin(args)], dim=-1)

class AdaLayerNorm(nn.Module):
    def __init__(self, dim, cond_dim):
        self.norm = nn.LayerNorm(dim, elementwise_affine=False)  # 不带自带的缩放/平移
        self.proj = nn.Linear(cond_dim, 2 * dim)                 # 用时间嵌入算出 scale 和 shift
    def forward(self, x, cond):
        scale, shift = self.proj(cond).unsqueeze(1).chunk(2, dim=-1)
        return self.norm(x) * (1 + scale) + shift                # 用时间动态调制归一化
🧩 为什么 (1 + scale)
初始化时 proj 输出≈0，于是 (1+scale)=1, shift=0，AdaLN 退化成普通归一化——这是个温和的"零初始化"技巧，让训练早期更稳，再慢慢学出时间相关的调制。

FlowMatchingBlock：自注意力 + 交叉注意力 + FFN

def forward(self, x, cond_tokens, time_emb):
    x = x + self.self_attn(*([self.norm1(x, time_emb)] * 3))[0]            # ① 两手查询互相看
    x = x + self.cross_attn(self.norm2(x, time_emb), cond_tokens, cond_tokens)[0]  # ② 看条件
    x = x + self.ffn(self.norm3(x, time_emb))                             # ③ 前馈
    return x

*([norm1(x)] * 3) 自注意力的 Q=K=V 都用同一份归一化后的 x（标准自注意力写法），让左右手两个查询彼此交换信息。

cross_attn(q=x, k=v=cond_tokens) 交叉注意力：查询是手的状态 x，键值是融合后的"物体+语言"条件。这一步把"该往哪抓"注入查询。

x = x + ... 三处都是残差连接，梯度好传、训练稳定。每个子层前先做 AdaLN（norm1/2/3 各带时间）。

FlowMatchingTransformer：组装与前向

def forward(self, x_t, t, cond_tokens):
    squeeze = False
    if x_t.dim() == 2:                 # 兼容单手 (B,31)；双手是 (B,2,31)
        x_t = x_t.unsqueeze(1); squeeze = True
    time_emb = sinusoidal_embedding(t, self.time_mlp[0].in_features)
    time_emb = self.time_mlp(time_emb)              # 时间 → 隐藏维
    x = self.input_proj(x_t) + self.query_pos[:, :x_t.shape[1]]  # 位姿升维 + 可学习查询位置
    cond = self.cond_proj(cond_tokens)              # 条件 768 → 256（对齐隐藏维）
    for block in self.blocks:                       # 6 层堆叠
        x = block(x, cond, time_emb)
    x = self.final_norm(x)
    v = self.output_proj(x)                         # 隐藏维 → 31，得到速度
    return v.squeeze(1) if squeeze else v

query_pos 形状 (1, num_queries, dim) 的可学习参数，给"左手/右手"两个查询各一个身份标识（位置编码）。

cond_proj 当条件维(768)≠隐藏维(256) 时用 Linear 投影；相等则是 nn.Identity()。

output_proj 最后把每个查询映射回 31 维——这就是该手位姿的"速度向量"。

🔑 它不直接输出姿势，而是输出"速度"
这正是流匹配的关键：模型是一个速度场 v(x,t,c)。怎么用速度生成姿势，看下面 dexvlg.py 的 sample。

models/dexvlg.py

总装车间
①②③④⑤ 串联 + 损失 + 采样

本文件含：SimpleTokenizer（兜底分词器）、FusionTransformer（模块④）、一组 BERT 加载函数、以及主类 DexVLG。

FusionTransformer（模块④）

def forward(self, pc_tokens, lang_tokens, lang_mask):
    pc   = pc_tokens   + self.pc_type_embed      # 给点 token 盖"几何"类型章
    lang = lang_tokens + self.lang_type_embed    # 给词 token 盖"语言"类型章
    combined = torch.cat([pc, lang], dim=1)      # 拼成 (B, 64+L, 768)
    pc_mask = torch.ones(pc.shape[0], pc.shape[1], dtype=torch.bool, device=pc.device)
    attn_mask = torch.cat([pc_mask, lang_mask.bool()], dim=1)
    key_padding_mask = ~attn_mask                # True 的位置=padding，注意力会忽略
    fused = self.encoder(combined, src_key_padding_mask=key_padding_mask)
    return self.norm(fused)

type_embed 两个可学习向量，让模型区分 token 来源（点 vs 词）。

key_padding_mask = ~attn_mask 点 token 全部有效(全 1)，语言部分用真实 mask；取反后告诉 Transformer 哪些是补白、别去注意。

语言模型加载：三层兜底 + "严格本地路径"

def _load_language_model(backbone, model_name, hidden_dim):
    looks_local = str(model_name).startswith(("pretrained_models","models/","./","../","/","~"))
    if looks_local:
        _, local_only = _resolve_pretrained_path(model_name)
        if not local_only:                       # 看着像本地路径却不存在 → 立刻报错
            raise FileNotFoundError(...)          # 绝不静默用随机权重
    backbone = (backbone or "bert").lower().replace("-","").replace("_","")
    if backbone in ("modernbert","modern"):
        return _load_modernbert(model_name, hidden_dim)
    return _load_bert(model_name, hidden_dim)

💡 register_buffer 是什么
把 flow_loss_weight 注册成"buffer"——它会跟着模型搬到 GPU、存进 checkpoint，但不是可训练参数（不参与反向传播）。persistent=False 表示不写进 state_dict（因为它由配置决定、可重建）。

encode_condition：得到"条件 c"（①→②→③→④）

def encode_condition(self, xyz, rgb, texts):
    pc_tokens = self.pc_encoder(xyz, rgb)         # ① (B,64,256)
    pc_tokens = self.projector(pc_tokens)         # ② (B,64,768)
    lang_features, lang_mask = self.encode_language(texts, xyz.device)  # ③ (B,L,768)
    return self.fusion(pc_tokens, lang_features, lang_mask)  # ④ (B,64+L,768)

compute_loss：流匹配训练损失（重点！）

def compute_loss(self, xyz, rgb, texts, gt_poses):
    cond_tokens = self.encode_condition(xyz, rgb, texts)
    t = torch.rand(B, device=device)              # 每个样本随机一个时刻 t∈[0,1]
    noise = torch.randn_like(gt_poses)            # 一团高斯噪声 ε
    t_expand = t[:, None, None].expand_as(gt_poses)
    x_t = (1.0 - t_expand) * noise + t_expand * gt_poses   # 噪声↔真值 的直线插值
    target_v = gt_poses - noise                   # 这条直线的恒定速度
    pred_v = self.flow_transformer(x_t, t, cond_tokens)    # 模型预测速度
    loss_fm = (self.flow_loss_weight * (pred_v - target_v) ** 2).mean()  # 加权 MSE
    return {"loss": loss_fm, "loss_flow_matching": loss_fm}

x_t = (1−t)ε + t·x₁ t=0 时是纯噪声，t=1 时是真值，中间线性过渡。

target_v = x₁ − ε 直线的速度恒定，与 t 无关——这就是模型要学的"标准答案速度"。

flow_loss_weight * 逐元素乘权重：平移×3、旋转×6、关节×1，防止 22 维关节淹没平移/旋转。全 1 时即普通 MSE。

sample：从噪声积分出姿势（推理）

@torch.no_grad()
def sample(self, xyz, rgb, texts, num_steps=50):
    cond_tokens = self.encode_condition(xyz, rgb, texts)
    x = torch.randn(B, 2, self.pose_dim, device=device)    # t=0 起点：随机噪声
    dt = 1.0 / num_steps
    for step in range(num_steps):                          # Euler ODE 积分
        t = torch.full((B,), step / num_steps, device=device)
        v = self.flow_transformer(x, t, cond_tokens)       # 当前速度
        x = x + v * dt                                     # 走一小步
    results = {}
    for i, hand in enumerate(["left", "right"]):           # 把 (B,2,31) 拆成两手
        pose = x[:, i]
        results[f"{hand}_translation"] = pose[:, :3]
        results[f"{hand}_rotation_6d"] = pose[:, 3:9]
        results[f"{hand}_joints"]      = pose[:, 9:]
    return results
🔑 训练学速度，推理用速度
compute_loss 教模型"任意中间点的速度该是多少"；sample 就反过来用：从噪声出发，反复问速度、走一步，10~50 步后到达姿势。两者共用同一个 flow_transformer。

forward：一个入口，两种模式

def forward(self, xyz, rgb, texts, gt_poses=None, num_steps=50):
    if gt_poses is not None:
        return self.compute_loss(xyz, rgb, texts, gt_poses)   # 给了答案 → 训练
    return self.sample(xyz, rgb, texts, num_steps)            # 没给答案 → 生成

models/pose_decoder.py

辅助工具
把位姿向量拆成 T/R/θ

一个小 MLP，把某个位姿特征解码成 {translation, rotation, joints} 字典。

def forward(self, x):
    out = self.decoder(x)                          # MLP: pose_dim → 31
    t     = out[..., :self.trans_dim]              # 前 3
    r     = out[..., self.trans_dim:self.trans_dim+self.rot_dim]  # 中 6
    theta = out[..., self.trans_dim+self.rot_dim:] # 后 22
    return {"translation": t, "rotation": r, "joints": theta}
💡 注意
主流程（dexvlg.sample）其实是直接切片 pose[:, :3]/[3:9]/[9:] 拆分的，并没有用这个解码器。PoseDecoder 是一个独立可复用的辅助模块（README 里也标注为"辅助工具"），理解它有助于看清 31 维的固定布局即可。

data/lgbidex_io.py

数据管线的底层纯函数
读文件 + 坐标/旋转变换

从 dexvlm 管线逐字移植来的一组纯函数，让本项目"自包含、不跨项目依赖"。挑几个关键的：

函数作用
axis_angle_to_matrix把数据集里的轴角旋转，用罗德里格斯公式变成旋转矩阵（再转 6D）
quaternion_to_matrix(·, order)把物体位姿的四元数(支持 wxyz/xyzw)变成矩阵
transform_points对点做"缩放 → 旋转 → 平移"的统一变换
shift_pose_translation只平移位姿的前 3 维（把抓取移到物体中心坐标系）
sample_uniform_points_from_mesh按三角面面积加权在网格表面均匀采点（用重心坐标）
load_point_cloud_from_ply / load_mesh_geometry手写 PLY/OBJ 解析器，支持 ascii / 二进制、带不带颜色
normalize_rotation_6d6D→矩阵→6D 走一圈，把 6D 重新正交化
🧩 面积加权采样为什么重要
如果对三角面"等概率"采样，大三角面和小三角面采到的点一样多，表面密度就不均。按面积加权（torch.multinomial(face_areas, ...)）才能让点在表面均匀铺开，几何更忠实。

data/dataset.py

把磁盘记录 → 模型输入
(xyz, rgb, text, pose×2)

核心是 DexGraspDataset。每条 JSON 记录含：obj_id, obj_pose(7), obj_scale, guidance, dex_grasp_left/right(28)。__getitem__ 把它变成模型要的格式。

__getitem__：一条样本的诞生

def __getitem__(self, idx):
    record = self.data[idx]
    xyz, rgb = self._build_point_cloud(record)      # 点云：加载→bbox中心化→按obj位姿摆放
    if self.augment:
        xyz, rgb = self._augment_point_cloud(xyz, rgb)   # 只做轻微抖动（见下方警告）
    pose_left  = self._build_hand_pose(record, "left")   # 28维→中心化→31维→(可选)归一化
    pose_right = self._build_hand_pose(record, "right")
    return {"xyz":xyz, "rgb":rgb, "text":self._build_instruction(record),
            "pose_left":pose_left, "pose_right":pose_right,
            "obj_id":..., "cate_id":..., "group_id":group_id_of(record)}

关键转换 1：点云的坐标处理

def _build_point_cloud(self, record):
    raw_pc, has_real_color = self._load_raw_point_cloud(obj_id)   # 缓存：按物体只加载一次
    bbox_center = self._load_mesh_bbox_center(obj_id)
    translation, rotation, scale = self._build_object_pose(record)
    xyz = raw_pc[:, :3] - bbox_center                # ① 平移到 bbox 中心
    xyz = transform_points(xyz, rotation_matrix=rotation, scale=scale)  # ② 按物体旋转+缩放
    if not self.center_on_object:                    # center_on_object=True 时物体留在原点
        xyz = transform_points(xyz, translation=translation)
    rgb = select_point_cloud_colors(raw_pc, ...)     # 真彩 or 常数填充
    return xyz, rgb

关键转换 2：抓取 28 维 → 模型 31 维

def _to_target_pose(self, pose):     # pose 是中心化后的 28 维
    translation = pose[:3]
    axis_angle  = canonicalize_axis_angle(pose[3:6])   # 轴角先规范化(角度绕到 [-π,π])
    joints      = pose[6:6+self.joint_dim]
    rotation    = normalize_rotation_6d(matrix_to_rotation_6d(axis_angle_to_matrix(axis_angle)))
    return torch.cat([translation, rotation, joints], dim=-1)   # [3 + 6 + 22] = 31

28 → 31 数据集存的是 [trans(3), axis_angle(3), joints(22)]=28；模型要 [trans(3), rot6d(6), joints(22)]=31。差别就在旋转：轴角(3) → 6D(6)。

canonicalize_axis_angle 把旋转角绕进 [-π,π]，消除"转 370° = 转 10°"这种等价表示带来的歧义。

collate_fn：把一批样本拼成 batch

def collate_fn(batch):
    result = {}
    result["xyz"] = torch.stack([b["xyz"] for b in batch])       # (B,N,3)
    result["rgb"] = torch.stack([b["rgb"] for b in batch])
    result["texts"] = [b["text"] for b in batch]                 # 文本保持 list（不 stack）
    pose_left  = torch.stack([b["pose_left"]  for b in batch])
    pose_right = torch.stack([b["pose_right"] for b in batch])
    result["gt_poses"] = torch.stack([pose_left, pose_right], dim=1)   # (B, 2, 31)
    ...
    return result
🔑 gt_poses 的 (B,2,31) 就是在这里诞生的
左右手两个 (B,31) 在第 1 维 stack，得到 (B,2,31)——正好对应生成器的 2 个查询。
⚠️ 为什么默认关闭增广
旧版本对点云做随机旋转，但只转了点云、没转抓取标签，会让点云和抓取"对不上"。所以现在 _augment_point_cloud 只做轻微的位置/颜色抖动，且配置默认 augment: false。
⚖️

data/pose_normalizer.py

位姿归一化
平移/关节 → [-1,1]

LgbidexPoseNormalizer 给左右手各一套 min-max 因子表，把 31 维位姿里的平移和关节缩放到 [-1,1]，6D 旋转原样通过。

def normalize_pose(self, pose):
    trans, rot6d, joints = self._split(pose)       # 拆成 3 / 6 / 22
    if self.mode == "minmax11":
        trans  = 2.0 * (trans  - tlo) / (thi - tlo + 1e-8) - 1.0   # 线性映射到 [-1,1]
        joints = 2.0 * (joints - jlo) / (jhi - jlo + 1e-8) - 1.0
    else:  # meastd11：用数据实测的均值/方差标准化
        trans  = (trans  - trans_mean)  / (2*trans_std  + 1e-8)
        joints = (joints - joint_mean)  / (2*joint_std  + 1e-8)
    return torch.cat([trans, rot6d, joints], dim=-1)   # 旋转不动
💡 为什么归一化能帮训练
流匹配的噪声先验是 N(0,1)（均值0、范围约 ±1）。把平移(米)、关节(弧度)缩放到同量级的 [-1,1]，目标分布就和噪声先验更匹配，模型更好学。旋转用 6D 已经天然有界，无需缩放。

denormalize_pose 是反操作，推理/验证后用它把预测变回真实米/弧度。build_hand_normalizers 根据配置一次造出 left/right 两套。

train.py

训练主循环
DDP + 混合精度 + best-K

训练一步的核心逻辑

with autocast("cuda", enabled=amp_enabled, dtype=amp_dtype):   # 混合精度
    outputs = model(xyz, rgb, texts, gt_poses=gt_poses)        # 走 compute_loss
    loss = outputs["loss"]

if not torch.isfinite(loss):          # NaN/Inf 保险：跳过这一步，不污染权重
    optimizer.zero_grad(set_to_none=True); scheduler.step(); continue

scaler.scale(loss).backward()         # 反向（fp16 时配合梯度缩放）
scaler.unscale_(optimizer)
torch.nn.utils.clip_grad_norm_(model.parameters(), grad_clip)  # 梯度裁剪防爆炸
scaler.step(optimizer); scaler.update(); scheduler.step()
⚠️ bf16 vs fp16（修改记录里的真实踩坑）
fp16 下 ModernBERT/PointNet 激活可能溢出成 inf，污染 BatchNorm 的 running 统计量，导致永久 NaN（GradScaler 只能跳过 optimizer step、救不了 forward 阶段被污染的 buffer）。所以 H100 上推荐 precision: bf16（范围等同 fp32、不溢出、且关闭梯度缩放）。get_amp_settings 负责解析这个配置。

validate：采样式验证（不是训练损失！）

with autocast(...):
    pred = net.sample(xyz, rgb, texts, num_steps=num_steps)   # 跑完整 ODE 采样
# 反归一化回真实单位，再分别算三项误差：
#   trans = 欧氏距离(米)   rot = 测地角(弧度)   joint = L1(弧度)
sums[0]+=trans...; sums[1]+=rot...; sums[2]+=joint...
return {"trans":..., "rot":..., "joint":..., "score": trans+rot+joint}

net.sample(...) 验证用的是真实采样（生成完整姿势再比对），比训练时的"单步流匹配损失"更能反映真实效果。

val_group_min 分支 开启后，每个预测与"同 (obj_id,pose_id,guidance) 组的所有 GT"比，取联合误差最小的候选——避免合法但不同的抓法被误判。

score = trans+rot+joint 三项之和作为选 checkpoint 的总分，越小越好。

best-K 检查点管理

def update_best_checkpoints(registry, score, keep_best_k, ...):
    if len(registry) >= keep_best_k and score >= registry[-1][0]:
        return registry, False                 # 不够好，不进 top-K
    path = f"best_e{epoch:04d}_s{score:.4f}.pt"
    save_fn(path); registry.append((score, path)); registry.sort()
    while len(registry) > keep_best_k:
        _, drop = registry.pop(); os.remove(drop)   # 淘汰最差的
    return registry, True

test.py

测试集评估
5 个指标
def compute_metrics(pred_poses, gt_poses, ...):
    for i, hand in enumerate(["left","right"]):
        trans_err = torch.norm(pred_trans - gt_trans, dim=-1).mean()    # 平移欧氏距离
        metrics[f"{hand}/trans_err_cm"] = trans_err * 100               # → 厘米
        rot_err = geodesic_distance(rotation_6d_to_matrix(pred_rot6d),
                                    rotation_6d_to_matrix(gt_rot6d))    # 旋转测地角
        metrics[f"{hand}/rot_err_deg"] = torch.rad2deg(rot_err).mean()  # → 度
        metrics[f"{hand}/joint_err_deg"] = np.degrees(torch.abs(pred_joints-gt_joints).mean())
        metrics[f"{hand}/trans_success_2cm"]  = (dist < 0.02).float().mean()   # 成功率
        metrics[f"{hand}/rot_success_15deg"]  = (rot_err < radians(15)).float().mean()

geodesic_distance 两个旋转矩阵的"夹角"：acos((trace(R1ᵀR2)−1)/2)，带 clamp(-1,1) 防数值越界。

success_2cm / 15deg 不只看平均误差，还看"有多大比例落在可接受阈值内"——更贴近"抓得成不成"。

evaluate 遍历测试集、采样、(可选)反归一化、累计指标；--save_predictions 时把每条预测存成 JSON。

调用关系串讲

把所有文件连成一条线

用一次"训练迭代"把所有文件穿起来：

train.py:main()
 └─ DexGraspDataset(...)                      # data/dataset.py
     ├─ _build_point_cloud  → lgbidex_io.load_point_cloud_from_ply / transform_points
     ├─ _build_hand_pose    → lgbidex_io.axis_angle_to_matrix → rotation 6D
     └─ (可选) pose_normalizer.normalize_pose
 └─ DataLoader(collate_fn) → batch{xyz, rgb, texts, gt_poses(B,2,31)}
 └─ DexVLG(cfg).forward(xyz,rgb,texts, gt_poses)   # models/dexvlg.py
     └─ compute_loss:
         ├─ encode_condition:
         │    ├─ PointNet2Encoder          # ① models/pointnet2.py
         │    ├─ projector (Linear×2)      # ②
         │    ├─ bert(input_ids,mask)      # ③ (Modern)BERT
         │    └─ FusionTransformer         # ④
         └─ flow_transformer(x_t,t,cond)   # ⑤ models/flow_matching.py → 预测速度
     └─ loss = 加权MSE(pred_v, gt−noise)
 └─ loss.backward() → optimizer.step()     # 更新所有模块参数
 └─ 每隔若干 epoch: validate() → model.sample()(跑ODE) → 反归一化 → 算指标 → best-K 保存
