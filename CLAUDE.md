# CLAUDE.md

## Project Overview

DexVLG bimanual dexterous grasp generation model. Generates language-conditioned grasp poses for two Shadow Hands (left + right) given a colored point cloud and natural language instruction.

## Tech Stack

- Python 3.10+, PyTorch 2.0+
- HuggingFace Transformers (BERT)
- Trimesh (mesh loading)
- Open3D (visualization, optional)

## Repository Layout

- `models/` — Neural network modules (DexVLG, PointNet++, FlowMatching, PoseDecoder)
- `data/` — Dataset and dataloader
- `utils/` — Rotation math, misc helpers, visualization
- `configs/` — YAML configuration
- `train.py` — Training with DDP
- `test.py` — Evaluation with metrics
- `inference.py` — Single-sample demo
- `test_sanity.py` — Quick model sanity check (no GPU needed)

## Code Conventions

- Type hints on all function signatures
- Docstrings on public classes and functions (Args/Returns format)
- No comments unless explaining non-obvious WHY
- 6D rotation representation throughout (Gram-Schmidt, not quaternion)
- Quaternion convention: wxyz (real part first)
- Pose vector layout: [trans(3), rot6d(6), joints(22)] = 31D per hand

## Key Design Decisions

- PointNet++ over Uni3D: pure PyTorch, no custom CUDA kernels needed
- BERT over Florence-2: encoder-only is sufficient for instruction encoding, much lighter
- Fusion Transformer: separate module rather than using LLM internals for fusion
- SimpleTokenizer fallback: allows running without downloading BERT weights (testing/CI)
- Flow-matching (not diffusion): deterministic ODE sampling, no noise schedule tuning

## Data Convention (LGBiDex format)

Splits are JSON arrays of records, one grasp per record. Input processing in
`data/dataset.py` (and `data/lgbidex_io.py`) mirrors the dexvlm pipeline's
`LgbiDexDataset` so both reproductions share coordinate conventions.

Per-object files under `mesh_root`:
- Colored point cloud: `{mesh_root}/{obj_id}/pc_part/simplified_part_{N}.ply`
- Mesh (fallback / bbox): `{mesh_root}/{obj_id}/mesh/simplified.obj`

Record fields:
- `obj_id`, `obj_pose` (7D = translation + wxyz quaternion), `obj_scale` (~0.1)
- `guidance` (instruction text), `cate_id`, `action`
- `dex_grasp_left` / `dex_grasp_right`: 28D `[trans(3), axis_angle(3), joints(22)]`

Processing: point cloud is bbox-centered and placed by the object rotation/scale
(`center_on_object`); grasp translations are shifted into the same frame and the
**axis-angle** rotation is converted to 6D. Output per hand is the 31D pose vector
`[trans(3), rot6d(6), joints(22)]`; the batch `gt_poses` is `(B, 2, 31)`.

## Checkpoint saving (`train.py`)

Three kinds of checkpoint land in `outputs/checkpoints/` (rank 0 only):
- `best_eXXXX_sX.XXXX.pt` — top-`keep_best_k` by validation score (evicts the worst when full).
- `last.pt` — **refreshed every epoch**; use it for `--resume` so an interrupted run continues from the newest epoch (`start_epoch = ckpt["epoch"] + 1`).
- `epoch_XXXX.pt` — numbered snapshot every `training.save_interval` epochs (default 20, `0` disables).

`save_interval` is a `training:` config key. Long runs must be launched under **tmux** (harness `run_in_background` gets killed at session boundaries).

### 1) Inference (`infer_dataset.py`, dexvlg env, GPU)

Samples per-hand poses, denormalizes, emits per-hand 28-d
`[translation(3), axis_angle(3), joints(22)]`, world frame. Output JSON has `pred_left` /
`pred_right` + `task_type` per record. `latent_ar` is task-agnostic: single-hand records
emit only their one `pred_*` (the other key is absent). `--task-type-filter` selects which
records to run (default: all).

### 2) Convert (`prepare_bench_data.py`, dexvlg / any numpy env) — four-channel dispatch

Dispatches each record by `task_type` to the right payload builder and writes each channel
to its own dir `<output_root>/<EXP>_<channel>_<hand_suffix>/graspdata` (left/lgbidex/bidex →
`shadow_left`, right → `shadow`). Two pose stages (verified conventions — do NOT re-add
flips/offsets):
- **pre/squeeze** (`compute_pregrasp(grasp, move_local)` + `compute_squeeze`): `pre = grasp −
  CLOSE_SIGN·0.1`, `squeeze = grasp + CLOSE_SIGN·0.1` on Shadow FLEX joints only. CLOSE_SIGN
  (joint idx): four-finger flex `{1,2,3,5,6,7,9,10,11,14,15,16}=+1`; thumb `THJ1(20)/THJ0(21)=−1`;
  abduction/rotation/metacarpal(LFJ4 12)/THJ4(17)/THJ3(18)/**THJ2(19)=0** (thumb slice is
  `pre[26:28]`, NOT `pre[25:28]`).
  - **Palm translation** (`move_local`): left/right/lgbidex = `[0,0,0]` (palm fixed).
    **bidex = `[0,+0.01,0]`** (local +Y = hand back): `pre[:3]=grasp[:3]+R@[0,+0.01,0]` (back off
    1cm) → mirror `squeeze[:3]=grasp[:3]+R@[0,−0.01,0]` (press 1cm **toward the palm**,
    `R@[0,-1,0]`, into the object) — the two opposed palms clamp the large object. Verified:
    `‖pre−grasp‖=‖squ−grasp‖=0.0100 m`, opposite directions, per-hand `R`.
- **28-d → bench 29-d qpos** (`gys_pose_to_bench_qpos`): `[trans, quat wxyz, 22 joints]`. Fuse
  data is **robot0/mjcf convention** (same as the bench), so the ONLY change is axis-angle →
  wxyz quaternion; **translation + 22 joints pass through UNCHANGED — NO sign flip, NO palm
  offset** (adding them CORRUPTS the data → GT baseline ~0%).

```bash
# bidex simultaneous grasp — FLOATING (no floor, hold in place, no lift)
$PY src/main.py task=eval4 setting=fc hand=shadow_left save_root=$S exp_name=dexvlg_v3_bidex_float task.lift_height=0 task.max_num=-1 n_worker=32

$PY src/main.py task=stat  hand=shadow_left save_root=$S exp_name=dexvlg_v3_left
$PY src/main.py task=stat  hand=shadow      save_root=$S exp_name=dexvlg_v3_right
$PY src/main.py task=stat3 hand=shadow_left save_root=$S exp_name=dexvlg_v3_lgbidex
$PY src/main.py task=stat4 hand=shadow_left save_root=$S exp_name=dexvlg_v3_bidex
```

- **eval4** (`src/task/eval_func/tabletop_bimanual_simul_mocap.py`) = both hands grasp/squeeze/
  hold **simultaneously**; `setting=tabletop`+`lift_height>0` lifts off a table, `setting=fc`+
  `lift_height=0` holds in free space. `succ = init_ok ∧ left/right no table pene ∧ object
  stable (Δpos<trans_thre ∧ Δangle<angle_thre)`.
- results in `evaluation/`, successes/failures symlinked under `succgrasp/` and
  `failgrasp/<fail_reason>/`. CPU-bound + embarrassingly parallel (`n_worker`); run under tmux.
- qpos layout (bench): `[xyz(3), quat wxyz(4), 22 joints]`; right-hand xml fixed to
  `assets/hand/shadow/right_hand.xml`.

## Offline metrics (`metric_eval/`, GAYS/DGTR reference implementations)

diversity + Q1 + FID. Coverage: **diversity covers all four task_types**
