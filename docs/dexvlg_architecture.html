全模型架构精讲

DexVLG：让两只机械灵巧手「听懂话、看懂物、做出抓」

一个语言驱动的双手灵巧抓取生成模型：给它一团带颜色的物体点云 + 一句自然语言指令，它就输出左右两只 Shadow Hand 该怎么摆位、怎么转、22 个关节各弯多少。

复现自 DexVLG (ICCV 2025) · 技术栈 PyTorch + Transformers(BERT/ModernBERT) · 全模型约 1.05 亿 参数 · 生成方式 Conditional Flow Matching（条件流匹配）

1这个项目到底在做什么

想象一个机器人面前放着一个杯子。你对它说一句话：「用双手抓住杯子准备倒水」。机器人需要算出：

  • 左手手腕放在空间哪个位置（3 个坐标）、朝向怎么转（旋转）、五根手指 22 个关节各弯曲多少度；
  • 右手同理。

DexVLG 就是负责"算出这套双手姿势"的大脑。它的本质是一个条件生成模型：

输入：物体点云(看) + 语言指令(听)　　→　　输出：左手 31 维姿势 + 右手 31 维姿势(做)
🎯 一句话类比
它像一位盲人雕塑家的助手：先用手摸遍物体表面（点云），再听你的口头要求（语言），然后凭经验"捏"出一套合理的手势。"捏"的过程不是一步到位，而是从一团随机噪声出发，一点点雕琢成形——这正是后面要讲的"流匹配"。

2小白扫盲：6 个核心名词

读懂这个模型，你只需要先弄明白这 6 个词。后面所有内容都建立在它们之上。

① 点云 (Point Cloud)

用一堆 3D 点来表示一个物体的形状。本项目每个物体用 4096 个点，每个点有 6 个数：(x, y, z, r, g, b)——前 3 个是空间位置，后 3 个是颜色。整团点云的形状就是 (4096, 6)。

💡 小白提示
把点云想成"用喷漆罐在物体表面喷出的 4096 个彩色小点"。点越多，形状越清晰。

② Shadow Hand 与 22 个自由度 (DOF)

Shadow Hand 是一只高度仿真的机械手，有 22 个可独立控制的关节（自由度）。给出这 22 个角度，手的姿态就完全确定了。本项目要为左右两只这样的手生成姿势。

③ 抓取位姿 (Grasp Pose)

描述"一只手怎么抓"需要 3 部分：手腕在哪（平移 T）、手腕朝哪（旋转 R）、手指怎么弯（22 个关节角 θ）。本项目把它们打包成一个 31 维向量。

④ 6D 旋转表示

表示"朝向"有很多方式（欧拉角、四元数…）。本项目用 6D 连续表示——它对神经网络最友好，不会出现四元数那种"突变/二义性"的问题。第 11 节会细讲。

⑤ Transformer 与注意力 (Attention)

一种能让信息"互相看一眼、按相关度交换"的网络结构。本项目用它做两件事：把点云和文字融合，以及让"抓取查询"去关注物体和指令。

🧩 类比
注意力就像开会：每个人（token）发言前先环顾全场，决定多听谁的、少听谁的，再综合出自己的下一句话。

⑥ 流匹配 (Flow Matching)

一种生成式方法（同类的还有扩散模型 Diffusion）。核心思想：学会一个"速度场"，能把一团随机噪声沿着直线"流"成一个合理的抓取姿势。第 10 节是全篇重点。

5模块①　PointNet++ 点云编码器

输入 (B,4096,3) 点云　→　输出 (B,64,256) 点 token

它的任务：把 4096 个零散的点，逐层浓缩成 64 个"懂几何"的特征向量（token）。靠的是反复做三件事：采样 → 分组 → 局部特征聚合，这套组合叫 Set Abstraction（集合抽象，SA）。

三步走（每一步 = 一个 SA 层）

SA 层点数变化搜索半径每组邻居特征维度
SA14096 → 5120.132→ 128
SA2512 → 1280.264→ 256
SA3128 → 640.464→ 256

每个 SA 层内部三个动作：

  1. 最远点采样 (FPS)：从当前点里挑出"分布最均匀、覆盖最广"的一批中心点。比如 4096 个点里挑 512 个代表。
  2. 球查询 (Ball Query)：以每个中心点为球心、给定半径画球，把球内的邻居点收进一组（不够就用最近的补齐）。
  3. 局部 MLP + 最大池化：把每组邻居（相对中心的坐标 + 特征）送进一个小型共享 MLP，再对组内取最大值，得到这个中心点的新特征。
🧩 类比：从"像素"到"地标"
就像看卫星地图时不断缩放：先看清每栋楼（4096 点），再归纳出每个街区（512），再归纳出每个区（128），最后归纳出 64 个"地标特征"。每缩放一级，点更少但每个点"理解"的范围更大。
⚠️ 一个容易困惑的配置点
默认配置 pc_in_channels: 3 表示只用 xyz、丢掉颜色。虽然代码里 encode_condition 永远把 rgb 也传进来，但编码器检测到 in_channels==3 时会自动把颜色丢弃。要用颜色就把它改成 6。
🔑 为什么选 PointNet++ 而不是原论文的 Uni3D
Uni3D 需要编译自定义 CUDA 核，部署麻烦。PointNet++ 是纯 PyTorch 实现（FPS / 球查询都用 torch.cdist 等原生算子写成），随处可跑，无需编译。

6模块②　Projector 投影对齐

输入 (B,64,256)　→　输出 (B,64,768)

点云特征是 256 维，语言特征是 768 维，两者维度不一样、没法直接拼一起。Projector 就是一座"翻译桥"，把每个点 token 从 256 维升到 768 维，让它和语言 token "说同一种语言"。

nn.Sequential(
    nn.Linear(256, 768),   # 升维
    nn.LayerNorm(768),     # 归一化，稳住数值
    nn.GELU(),             # 非线性激活
    nn.Linear(768, 768),   # 再做一次变换
)
💡 小白提示
这一步本身不"理解"内容，只负责把点云特征"摆"到和语言同一个 768 维空间里，方便下一步融合。这是多模态模型里非常常见的套路，叫 projection / alignment（投影对齐）。

7模块③　BERT / ModernBERT 语言编码器

输入 字符串列表　→　输出 词 token (B,L,768) + 注意力掩码 (B,L)

它把"Grasp the mug"这样的句子，先用 tokenizer（分词器） 切成一串数字 id，再用 BERT 编码成一串 768 维的"词向量"。BERT 是 encoder-only 的双向语言模型，擅长"理解"句子含义。

三种加载策略（代码很贴心地做了兜底）

策略什么时候用
BERT（默认）加载 bert-base-uncased 或本地权重
ModernBERT2024 年的现代双向编码器，hidden=768 与 BERT 对齐，可一键替换（默认配置就用它）
SimpleTokenizer + 随机 BERT离线/没下载权重时的兜底，用哈希分词 + 随机初始化，保证测试/CI 能跑通
⚠️ "看起来像本地路径却找不到"会直接报错
代码特意区分了两种失败：如果你配的是本地路径（如 pretrained_models/...）但目录不存在 → 直接报错，绝不静默回退随机权重（避免你以为在用预训练、实际在用随机权重白练一场）；只有非本地的 HF id 离线拉取失败才回退随机。
🔑 为什么用 BERT 而不是原论文的 Florence-2
抓取任务只需要"理解指令"，不需要"生成文字"，所以一个 encoder-only 的轻量 BERT 就够了，比庞大的 Florence-2 LLM 高效得多。

8模块④　Fusion 融合 Transformer

输入 点 token (B,64,768) + 词 token (B,L,768)　→　输出 条件 tokens (B,64+L,768)

到这里，点云和文字都被翻译成了同一空间的 768 维 token，但它们还是"各说各话"。Fusion Transformer 的任务：让它们互相注意、深度交融，产出一份统一的"条件"——既知道物体长什么样，又知道你想怎么抓。

它做了三件聪明事

  • 打类型标签：给所有点 token 加一个可学习的 pc_type_embed，给所有词 token 加 lang_type_embed，让模型分得清"这是几何信息"还是"这是语言信息"。
  • 拼接后过 4 层 Transformer 编码器：每一层里，所有 token（点+词）彼此做自注意力，信息充分交换。
  • 处理 padding 掩码：句子长短不一，短句补了空白(pad)；用 key_padding_mask 告诉注意力"别理那些空白位置"。
🧩 类比
这就像让"摸过物体的人"和"听过指令的人"坐到一张桌子上开会(自注意力)，会开完，每个人都同时掌握了形状信息和语言意图。会议纪要(融合后的 tokens)就是后面生成器要参考的"条件"。
🔑 设计选择
原论文借 Florence-2 的 LLM 内部来融合；本项目用一个独立的 4 层 Transformer 专门做融合，结构更清晰、更可控。

9模块⑤　Flow-Matching Transformer（生成核心）

输入 含噪位姿 x_t (B,2,31) + 时间 t (B,) + 条件 c (B,64+L,768)　→　输出 速度场 v (B,2,31)

这是整个模型真正"生成动作"的部分，采用 DiT（Diffusion Transformer）风格。它内部有 2 个查询 token——一个代表左手、一个代表右手。这 2 个查询从噪声开始，在条件 c 的引导下被反复"去噪"，最终变成两套合理的位姿。

一个 Flow-Matching Block 的三步（共 6 层）

  1. 自注意力（self-attention）：左手查询和右手查询互相看——这让"双手协同"成为可能（比如两只手不会抓到同一个地方）。
  2. 交叉注意力（cross-attention）：两个手查询去"看"条件 tokens c（物体+指令），从中抽取"该往哪抓"的信息。
  3. 前馈网络（FFN）：逐 token 做一次非线性变换，增强表达力。

时间是怎么注入的：AdaLN（自适应层归一化）

生成过程有一个"进度" t（从 0 到 1）。模型需要知道"现在雕到第几步了"。做法是把 t 先变成 正弦时间嵌入，再用它去动态生成每个归一化层的缩放 scale 和平移 shift：

AdaLN(x, t) = LayerNorm(x) · (1 + scale(t)) + shift(t)
💡 小白提示
普通 LayerNorm 的缩放/平移是固定学出来的；AdaLN 让它们随时间 t 变化。等于告诉网络："去噪早期和晚期要用不同的'力道'"。这是 DiT/扩散类模型注入时间条件的标准手法。
🔑 为什么左右手用"2 个查询"而不是两个独立模型
共享同一个生成器、用 self-attention 让两手互相感知，能学到双手配合的关系，比各算各的更协调。

10核心原理：流匹配怎么生成抓取

这是全篇最重要、也最"反直觉"的一节。耐心看完，你就抓住了模型的灵魂。

大白话版

我们想生成一个"合理的抓取姿势"，但姿势空间太大、没法直接预测。流匹配的思路是：

🎬 类比：把"雪花噪点"还原成"清晰照片"
想象一段视频：第 0 帧是纯电视雪花(随机噪声)，最后一帧是清晰照片(真实姿势)，中间是平滑过渡。流匹配训练模型学会"每一帧该往哪个方向变、变多快"（速度）。生成时，只要从雪花出发，按学到的速度一帧帧推进，就能"流"成清晰照片。

训练阶段：学"速度场"

对每个真实姿势 x₁（标准答案），随机配一团噪声 ε 和一个时刻 t∈[0,1]，在它俩之间走直线插值：

x_t = (1 − t)·ε + t·x₁ ← 噪声(t=0) 到 真实姿势(t=1) 的直线上某一点
target_v = x₁ − ε ← 这条直线的"速度"（方向×大小，恒定）

然后让模型看着 x_t、t 和条件 c，去预测这个速度，预测得越准越好：

loss = 加权均方误差( 模型预测的 v , target_v = x₁ − ε )
🔑 为什么直线插值这么妙
因为直线的速度是恒定的 x₁−ε，不随 t 变。模型只要学会"在任意中间点，指出通往真实姿势的方向"即可。训练目标极其干净——不像扩散模型要调一堆噪声系数表。

关于损失加权（一个实战细节）

31 维里关节占了 22 维，如果直接算 MSE，关节会"淹没"只有 3 维的平移和 6 维的旋转。所以配置里给了 分量权重：

translation × 3.0　　rotation × 6.0　　joint × 1.0

这样平移和旋转就不会被关节"带偏"，三者都能学好。（全设 1.0 就退回普通 MSE。）

推理阶段：从噪声"流"出姿势

训练好速度场后，生成就是解一个常微分方程(ODE)，用最简单的 欧拉法 一步步走：

x = 随机噪声  N(0,1)            # 形状 (B, 2, 31)，t=0 的起点
dt = 1 / num_steps
for step in range(num_steps):   # 默认 10 步（或 50 步）
    t = step / num_steps
    v = flow_transformer(x, t, c)   # 当前点的速度
    x = x + v * dt              # 沿速度走一小步
# 走完 num_steps 步，t 到 1，x 就是生成的双手姿势
🧩 类比：盲人下山
你站在山上(噪声)想到达山脚的某个目标(姿势)，但看不见路。模型扮演向导，每走一小步就告诉你"现在该朝哪个方向"。走 10~50 小步，你就到了。步数越多越精细，但越慢——这就是 num_steps 的权衡。
🔑 流匹配 vs 扩散：为什么选流匹配
流匹配是确定性 ODE 采样，不需要扩散模型那套复杂的"噪声调度表"调参，路径更直、采样更快、更稳。这是本项目相对原论文的一个工程取舍。

11位姿表示：31 维拆解

每只手的姿势被打包成一个 31 维向量，布局固定：

[ 平移 T (3) | 旋转 R 的 6D 表示 (6) | 关节角 θ (22) ] = 31 维
成分维度含义
Translation T3手腕在物体中心坐标系下的 (x,y,z)
Rotation R (6D)6手腕朝向，用旋转矩阵的前两行表示
Joints θ22Shadow Hand 22 个关节角

为什么旋转要用"6D"这么奇怪的表示

神经网络喜欢"连续、无突变、唯一"的表示。常见旋转表示的毛病：

  • 欧拉角：有"万向锁"，且 360°=0° 不连续；
  • 四元数：q 和 −q 表示同一个旋转(二义性)，且被约束在单位球面上，对回归不友好。

6D 表示的做法：取一个 3×3 旋转矩阵的前两行（共 6 个数）。需要还原成完整旋转矩阵时，用 Gram–Schmidt 正交化：

b1 = normalize(a1) # 第一行归一化
b2 = normalize(a2 − (b1·a2) b1) # 第二行去掉 b1 分量后归一化（变正交）
b3 = b1 × b2 # 第三行 = 前两行叉乘
💡 小白提示
不管网络吐出什么 6 个数，Gram–Schmidt 总能把它"修正"成一个合法旋转。所以这个表示连续、无死角、网络好学。这是图形学论文《On the Continuity of Rotation Representations》提出的经典技巧。

代码里 utils/rotation.py 提供了四元数↔矩阵↔6D 的全套互转；数据加载时把数据集里的 axis-angle(轴角) 旋转转成 6D 喂给模型。

12训练 vs 推理：同一个模型，两种跑法

🏋️ 训练（train.py）
  • 喂入 gt_poses，走 单步 流匹配损失：随机一个 t，算 x_t，预测速度，比对 target_v；
  • 优化器 AdamW + 余弦学习率(带 warmup)；
  • 支持 多卡 DDP 和 混合精度（推荐 bf16，fp16 易溢出导致 NaN）；
  • 对非有限(NaN/Inf)的 loss 自动跳过该步，防止污染权重；
  • 每隔若干 epoch 跑一次"完整采样式验证"，按分数只保留最好的 K 个 checkpoint。
🔮 推理（sample / test / inference）
  • 不给答案，从噪声出发跑 多步 ODE 积分生成姿势；
  • 若训练时开了归一化，输出要反归一化回真实单位（米 / 弧度）；
  • 把 6D 旋转转回四元数，得到可直接驱动机械手的姿势；
  • inference.py 还能用 Open3D 把点云 + 双手姿势可视化出来。
⚠️ 关于"归一化"
训练时平移和关节会被 min-max 缩放到 [-1,1]（让数据分布更贴近流匹配的 N(0,1) 先验），6D 旋转保持不变（只重新正交化）。这意味着开/关归一化的 checkpoint 语义不同、不可混用，切换后必须重训。

13怎么评判好不好（评估指标）

指标衡量什么越…越好
trans_err_cm手腕平移误差（厘米）越小
rot_err_deg旋转测地角误差（度）= 两个朝向差多少度越小
joint_err_deg关节角平均误差（度）越小
trans_success_2cm平移误差 < 2cm 的比例越大
rot_success_15deg旋转误差 < 15° 的比例越大
💡 "组内最佳匹配"验证
同一个物体+同一句指令，往往有多种都对的抓法。如果只跟"某一个标准答案"比，模型生成了另一种合法抓法反而被判错。所以验证时可开 val_group_min：把预测和"同组所有标准答案"比，取最接近的那个算误差，更公平。

14与原论文 DexVLG 的差异

组件原文 DexVLG本实现为什么改
点云编码器Uni3DPointNet++纯 PyTorch，无需编译 CUDA 核
语言模型Florence-2 LLMBERT / ModernBERT抓取只需"理解"，encoder-only 更轻
多模态融合Florence-2 内部独立 4 层 Fusion Transformer结构清晰、可控
抓取目标单手双手（左右各 31 维）支持双手协同抓取

15一页纸总复习

🔑 把整个模型讲给朋友听（30 秒版）

「DexVLG 是个双手灵巧抓取生成器。PointNet++ 把物体点云压成 64 个几何 token，Projector 升维到 768 对齐语言；BERT 把指令编码成词 token；Fusion Transformer 把点和词融合成统一'条件'。然后一个 DiT 风格的流匹配 Transformer 拿着 2 个查询(左右手)，从随机噪声出发，在条件引导下跑 10~50 步 ODE 积分，'流'出左右手各 31 维的位姿——平移3 + 6D旋转 + 22关节。训练时学'噪声→真值'的恒定速度场，推理时沿速度场积分生成。」

①PointNet++ 4096点→64token ②Projector 256→768 ③BERT 句子→词token ④Fusion 点+词融合 ⑤FlowMatching 噪声→姿势 输出 2×31维
